EventVLA · method

EventVLA：把「何时该记住」变成预测问题

记忆 M_t = A_t ∪ E_t

  • 锚帧 A_t = {o₀} ∪ {o_{t−30}, o_{t−15}}：全局布局 + 运动线索（规则）
  • 事件帧 E_t：KEM 写入，N_max = 5，FIFO
  • 输入 concat([A_t, E_{t−1}, o_t]) 直接进 VLM 视觉编码器——「读」就是多帧注意力
p̂_t = σ(MLP(h_t)) ∈ [0,1]^H, H = 50  ·  写入若 p̂_t^i ≥ 0.55 → 存 o_{t+i}

1-D NMS（w = 8）+ 冷却（C = 10）防止同一事件灌满缓冲区

训练

  • 标签：Qwen3-VL-235B 离线看演示输出关键帧步（仿真误差 < 10 步，真机 < 50 步）
  • 软标签：升余弦核 y = ½(1 + cos π|t+i−t*|/R)
  • L = L_action + 0.1 · L_kem
  • 师生课程：真值缓冲 → 自身预测，α: 1 → 0

为什么按整块预测

事件常在一个动作块中途出现又消失，逐步分类器来不及；共享 h_t 让 KEM 知道策略接下来要做什么，能预约一次写入。

基座：QwenOFT (Qwen3-VL-4B) / 真机 π₀.₅4 / 18

TRACE · method

TRACE：用「走过的路」给记忆编地址

延迟证据 → 内容与地址分离

  • 短窗口下 x_{t−w+1:t} ≈ x′_{t−w+1:t} 但 a*_t(H_t) ≠ a*_t(H′_t)
  • 内容 e_t = φ_x(x_t)：多视角视觉 + 本体感受
  • 地址：17 维状态路径的深度-3 路径签名，17 + 17² + 17³ = 5219 维，加增量 δ_t = ξ_t − ξ_{t−1}
  • 对时间重参数化、常数偏移不变，对顺序敏感；流式 0.52 ms
ω_{t,k} = softmax_k(⟨W_Q ρ_t, W_K m̄_{t−1,k}⟩ / τ√d)  ·  m_{t,k} = (1−β) m_{t−1,k} + β m̃_{t,k}

适配器只做翻译

  • ACT：槽 → 512 维记忆 token 拼进注意力 memory（+0.79 M）
  • Diffusion：池化 → 零初始化 MLP → 加性全局条件（+16.03 M）
  • 共享更新器 11.91 M；骨干、动作头、损失都不改

三个稳定器（只作用于记忆）

L_bal 防槽塌缩 · L_ent 防弥散写入 · L_cons 防读写失配；去掉它们 69.23 → 66.10

K = 4 / 6 槽 × 512 维；训练与部署同一条因果扫描，不用线索 / 分支标签6 / 18

Insights 1–5

十个洞见（1–5）

  1. 前沿从「存多少」转到「何时写」——EventVLA / KEMO / UniMem / WeaveLA / MemoryWAM / TFP 从不同架构同时转向事件驱动稀疏写入；TFP 测得事件附近写入增益 ≈ 6×
  2. 机理（Present but Not Remembered）——冻结 VLA 里的历史是当前帧的冗余副本，只属于过去的信息几乎不存在 ⇒ 记忆增强应注入过去独有的信息
  3. 原图 vs latent 取决于要恢复多少比特——EventVLA 24.9 vs 75.2（3–5 个视觉细节）与 TRACE 69.23（1–2 比特分支变量）并不矛盾；计数用符号（AGM / HyMeS）
  4. 寻址被低估——TRACE 让写入时刻与读取时刻有稳定对应（保序 ~90，倒序 37.8）；分支若不对应运动差异则退化
  5. 长上下文没那么脆，但虚假相关是真的——Agarwal et al. 的扫描 vs PTP / GMP（+30.1）/ HALO：能否用长窗口取决于监督是否把注意力引向任务相关历史

Insights 6–10

十个洞见（6–10）

  1. 可靠性来自有纪律的状态更新，不是容量——AGM 验证后推进、EventVLA NMS + 冷却、TRACE 门控写入、BATON 验证器：记忆写入应是带验证的事务
  2. 双系统在计数与过程记忆上仍领先——PonderPounce（p50 78 ms 刷新 / 25 ms 动作）在缩小延迟劣势；分界线变成「哪类信息放哪一层」
  3. 记忆成本趋近于零——NativeMEM 每帧 1 token、TempoFit 免训练、StreamPI 零参数、DySta 2× 加速；EventVLA 的 3× 延迟会被后继者先优化
  4. 多机器人是同一问题的另一张脸——搭档相位 = 从历史推断的隐变量；SAI 只有 30 步 GRU，无人把显式记忆用于搭档状态估计
  5. 评测在分裂，诊断在成熟——一年 12 套基准；TRACE 顺序反转负对照、探针 + 因果干预、TFP 隐状态干预 ⇒ 同时报告「成功率」与「记忆用了什么」

Open problems & next steps

开放问题与我们的下一步

开放问题

  • 缓冲区饱和：5 帧 FIFO（> 10 min）；固定槽 2× 历史一致性 0.928
  • 签名维度立方增长：深度 4 → 88,740 维；高维人形需 log-signature
  • 写入触发的监督：235B 标注 / 规则 / 分类器 / rollout 结果，无跨任务对照
  • 记忆与动作块长度耦合（75.2 → 13.6）；错误记忆的安全性（AGM）
  • 基准统一：RoboMME 四类 + RoboTwin-MeM 的 n + TRACE 阶段进度

研究方向

  1. 前瞻写入 × 轨迹寻址：KEM 决定何时写，签名决定写到哪；在 RoboTwin-MeM 与 TRACE 任务上同时验证
  2. 搭档相位记忆：SAI 的 30 步 GRU → 签名槽记忆（键 = A 的轨迹，内容 = 对 B 的观测）
  3. 记忆诊断基准：RoboMME 四类任务各配保序 / 破序变换，路由相似度成为标准报告项
  4. 写入触发的跨任务迁移：同骨干对照学习 / 规则 / 分类器三种触发

Method lessons

三篇论文教给我们的方法论

把一个默认做法拆开单独测

EventVLA 只换记忆表征（原图 vs latent）；TRACE 只换寻址（有无签名路由、有无增量）；SAI 只换数据课程（架构固定）。说服力来自单变量对照。

报告代价

EventVLA 报延迟（0.94 Hz），TRACE 报每步毫秒与参数增量（+24.6% / +10.3%），SAI 报干预数据占比（30%）。读者能判断收益是否值得。

用诊断替代猜测

TRACE 的顺序反转负对照把「记忆在用历史」从假设变成可测量；Liao & Cao 的探针 + 因果干预回答「历史是不是当前帧的副本」。

Takeaways

三句话带走

记忆的四问
记什么 / 何时写 / 写到哪 / 存多少，比「要不要记忆」重要；EventVLA 与 TRACE 各答了一问的极端，中间地带空着。
表征跟信息量走
要恢复多个视觉细节用原图（75.2 vs 24.9），要恢复分支变量用槽（69.23），要计数用符号（AGM / HyMeS）。
用诊断代替猜测
把历史倒放看记忆读出变不变（TRACE）；用探针看历史是否只是当前帧的副本（Liao & Cao）。
